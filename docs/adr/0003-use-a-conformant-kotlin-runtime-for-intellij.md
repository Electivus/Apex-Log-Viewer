# Use a conformant Kotlin runtime for IntelliJ

Status: accepted

The IntelliJ plugin will implement Salesforce and Apex Log Lifecycle behavior in a JVM-native Kotlin runtime instead of executing `@alv/core` through a Node sidecar or depending on `sf electivus`. This runtime is an intentional IntelliJ-only implementation: the VS Code extension and Salesforce CLI plugin remain adapters over the TypeScript `@alv/core`. Language-neutral fixtures and conformance contracts must cover the shared invariants and DTO semantics so behavior drift between the Kotlin and TypeScript runtimes is detected rather than silently accepted.

The Salesforce CLI remains required only as the authentication broker. The Kotlin runtime discovers orgs through `sf org list --json`, obtains an access token and instance URL through `sf org display --json`, keeps credentials in memory without logging them, and performs Salesforce Tooling REST operations itself. An authentication failure may trigger one credential refresh and retry; the plugin does not read private Salesforce CLI auth files or own a second OAuth lifecycle.

The IntelliJ presentation is implemented with Kotlin and the native IntelliJ Platform UI rather than JCEF, and it does not reuse the React webview components. Functional parity is specified through observable behavior and shared fixtures instead of shared UI code, while each IDE remains free to follow its own interaction conventions.

One lazily initialized project tool window contains the Logs surface, and a Parsed Log Viewer opens in a dedicated IntelliJ editor. The first release excludes Debug Flags, DebugLevel management, and remote log cleanup. It retains the Parsed Log Viewer because Illuminated Cloud 2's raw-text, tree, and replay presentations do not replace the Apex Log Viewer-owned Debug, SOQL, DML, Errors, search, and triage perspectives.

The Logs surface combines the remote Apex log catalog with Unified Log Search across metadata and dependable local bodies. Normal browsing materializes bodies in the background only for catalog pages the user has loaded, while an active search may fetch additional pages and bodies to discover matches. Remote search progresses in bounded batches over a stable catalog snapshot, and every successfully acquired body joins the normal Apex Log Lifecycle for reuse instead of becoming a temporary search artifact. Search text remains local and is never sent to Salesforce. Downloading the complete available backlog outside a search remains an explicit Download All operation. The focused native table keeps a fixed initial column set with ordinary resizing instead of persistent column customization. A bounded content check may admit an external Salesforce `.log` through an explicit Open in Apex Log Viewer action, but the standard text editor continues to own unrelated `.log` files.

Open Raw Log opens the dependable local `.log` file in the standard text editor. Replay Handoff is presented as Open in Illuminated Cloud 2 from both the selected Logs row and the Parsed Log Viewer. If the selected body is still pending, the handoff first materializes it with visible progress and then passes the dependable file through the registered Log Analyzer action. Apex Log Viewer neither owns nor starts offline replay debugging.

The first release supports IntelliJ IDEA 2026.1 and 2026.2. It compiles against the 2026.1 platform and Java 21 baseline, runs Plugin Verifier against both supported IDE lines, and adds a real smoke test against the locally installed IntelliJ IDEA Ultimate 2026.2.

The declared products are IntelliJ IDEA Community and Ultimate. Illuminated Cloud 2 is an optional runtime integration for Replay Handoff rather than a required plugin dependency. The integration resolves the registered `IlluminatedCloud.LogAnalyzer.Open` action at runtime and supplies only the current project and dependable local log through the IntelliJ Platform Action System; it does not import or reflect over Illuminated Cloud implementation classes. If the action is absent or cannot be invoked, Apex Log Viewer retains raw-log opening and explains that the optional handoff is unavailable. Other JetBrains IDE products are outside the first-release compatibility claim.
